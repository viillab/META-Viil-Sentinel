## Proposed optional future response projection (NOT an existing API)

Only after Member 2's authenticated backend, never from raw model output:

```json
{
  "meta_review_v1": {
    "schema_version": "viil.backend.meta_review.v1",
    "provider": "meta_model_api",
    "actual_provider_request_succeeded": true,
    "backend_validated": true,
    "source_authenticated": true,
    "evidence_authorized": true,
    "evidence_frame_count": 2,
    "verdict": "fall_likely",
    "route": "auto_notify_informational",
    "supporting_frame_indices": [0, 1],
    "fall_confirmed": false,
    "emergency_dispatch_authorized": false,
    "medical_triage_authorized": false
  }
}
```

**This is an illustrative contract, not test evidence of Meta access.**
Member 2 may refine it only by coordinating a versioned schema review.
The adapter checks exactly the expected 13 keys, types, provenance,
evidence window bounds and consistency; non-simulated events without
the DTO stay `pending` and bad DTOs are `invalid`. If
`simulated` is true or the observation is generated by `mock`,
it ALWAYS reports `mock`, even when the payload claims real provider.

Do not let the browser treat these fields as *security authority*.
Member 2 must validate source ownership, evidence consent, model
execution and review results server-side. The frontend's only output
is **passive text**:

| Display state | Safe meaning |
|---|---|
| MOCK · DEMONSTRATION | Fake/local incident; no real Meta |
| META VERIFICATION · PENDING | No future backend result yet |
| EVIDENCE INSUFFICIENT | Invalid, missing or unauthorized trusted fields |
| META · FOLLOW-UP REQUIRED | Non-positive/uncertain or follow-up route |
| META · INFORMATIONAL ADVISORY | Future backend-reported likely fall with verified evidence; not a confirmed fall or emergency action |

The current Edge `viil.edge.candidate.v1` is a separate unconfirmed
**local stdout** contract. This proposed projection is a later stage
of Member 2's authenticated backend, *not* an Edge emitter field.
